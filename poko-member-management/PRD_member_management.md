## 2 产品概述

### 2.1 产品定位

会员管理模块是代购集运SaaS平台的基础模块，面向租户运营人员提供C端会员的全生命周期信息管理。每个C端用户即为一个会员，按租户隔离归属；会员注册时需实时同步至底层服务平台（物流商+WMS集合体），以支持后续仓储、提包、物流等核心操作。

### 2.2 产品目标

- 建立清晰的会员数据模型，支持邮箱注册和第三方快捷登录两种方式
- 实现会员与服务平台的注册同步机制，保障仓储物流链路可用
- 为租户运营人员提供会员列表查询、详情查看、启用/禁用、同步重试等核心管理能力
- 提供代购订单、提包单、积分、优惠券、余额、消费记录、售后记录等业务数据的详情展示入口
- 支持收货地址管理和实名认证能力

### 2.3 系统架构

详见飞书文档中的架构图。

> **数据主从原则：** 会员信息以代购平台为准；服务平台仅作为物流和仓储能力的执行方，会员数据不从服务平台反向同步。

### 3.2 核心场景

**场景1：新用户邮箱注册**

C端用户在代购平台填写邮箱、密码完成注册，系统自动创建会员记录并实时调用服务平台接口创建对应账号。同步成功后，会员可正常使用仓库、提包等功能。

**场景2：第三方快捷登录注册**

C端用户使用Google账号快捷登录，系统检测该第三方账号未绑定会员。若第三方返回邮箱且平台未注册过，自动创建会员记录并绑定，全程无额外验证码。若第三方未返回邮箱，强制用户输入邮箱并通过验证码验证归属权后，再创建会员记录和绑定记录。随后同步至服务平台。

**场景3：运营人员查询会员**

运营人员在会员列表页通过邮箱/昵称搜索、状态筛选等方式定位目标会员，查看其注册时间、消费数据、仓库待处理数等关键指标。

**场景4：同步失败处理**

某会员注册时因服务平台网络抖动导致同步失败，系统自动重试3次后仍未成功。运营人员在列表页看到该会员同步状态为"同步失败"，点击"同步重试"手动触发，同步成功后状态恢复正常。

**场景5：运行时服务平台异常**

某会员正常使用过程中，服务平台冻结了该会员账号，导致仓库操作失败。系统捕获异常后将会员同步状态标记为"同步失败"，前端提示"服务暂时不可用，请联系客服处理"，不自动重试。

**场景6：禁用违规会员**

租户管理员发现某会员存在违规行为，在列表页或详情页点击"禁用"，选择禁用原因并确认后，会员状态变为禁用，该会员无法登录和使用平台。

**场景7：收货地址实名认证**

会员在C端添加收货地址后，系统使用当前收货地址的身份证号及姓名，调用台湾易利委接口进行实名认证验证。验证成功后，后台详情页收货地址Tab中该地址的实名状态显示为"已实名"，验证失败则显示"未实名"。

## 5 业务规则与业务模型结论

### 5.1 会员状态模型

会员状态由两个独立维度组合判断：

**会员状态（status）— 人工控制：**

详见飞书文档中的会员状态表。

**同步状态（sync_status）— 系统控制：**

详见飞书文档中的同步状态表。

**前端组合展示规则：**

详见飞书文档中的展示规则表。

> **注意：** 登录时仅校验会员状态（status），不校验同步状态（sync_status）。同步状态仅在业务节点（提交集运包裹、查询物流等需要service_member_id的操作）进行检查和提示。

### 5.2 状态流转

```
注册成功 → 同步中 → 已同步（正常使用）
                ↘ 同步失败 → 自动重试 → 已同步
                                              ↘ 超过3次 → 同步失败（人工重试）

正常使用中 → 服务平台异常 → 同步失败（不自动重试，人工介入）

任意状态 → 管理员禁用 → 禁用
禁用 → 管理员启用 → 正常
```

### FR-18 第三方快捷登录/注册流程

#### 第三方登录完整流程规则：

**第一步：检查是否已绑定**
- 用 (provider, open_id) 查询 member_oauth_binding 表
- **已绑定** → 获取会员记录 → 检查会员状态 → 正常则登录成功，禁用则拒绝
- **未绑定** → 进入第二步

**第二步：邮箱处理（email为必填项）**
- **第三方返回了邮箱**：直接使用该邮箱继续流程
- **第三方未返回邮箱**：强制用户手动输入邮箱，发送验证码验证归属权（验证码规则：6位数字、15分钟有效、60秒限发、连续5次错误锁定1小时）

**第三步：检查邮箱是否已在平台注册**
- **邮箱未注册过**（无论邮箱来自第三方返回还是手动输入后验证通过）：
  - OAuth返回的邮箱：平台信任其归属权，直接创建会员记录 + 创建第三方绑定记录 → 登录成功
  - 手动输入的邮箱：验证通过后同样创建会员记录 + 创建第三方绑定记录 → 登录成功
  - 全程无需额外验证码
- **邮箱已存在**：
  - 检查该会员是否已绑定**相同provider**的其他open_id → **是则拒绝**，提示"该邮箱已绑定XX账号，请先登录原账号解绑"
  - 该会员绑定的是**不同provider** → 进入第四步

**第四步：验证码绑定已有会员**
- **邮箱来自第三方OAuth返回**：需发送验证码到该邮箱，用户输入验证码确认归属权
- **邮箱来自用户手动输入（第三步已验证过）**：跳过验证码，直接进入第五步（避免重复验证）

**第五步：绑定并登录**
- 验证码校验通过（或跳过）后 → 检查会员状态 → 正常则创建第三方绑定记录 → 登录成功；禁用则拒绝

**关键规则说明：**
- **登录时不校验同步状态**（sync_status），仅校验会员状态（status）。sync_status在业务节点（如提交集运包裹、查询物流等需要service_member_id的操作）才检查：状态0/2提示"同步中请稍后"，状态3提示"服务异常，请联系客服"
- **所有会员必须有邮箱**，不允许创建无邮箱的会员记录
- **同provider已绑定必须拒绝换绑**，必须先登录原账号解绑
- 验证码规则：有效期15分钟、6位数字、60秒限发、连续5次错误锁定1小时

## 15 层级交接摘要

### 给开发的核心要点

1. **系统定位：** 会员管理是SaaS平台基础模块，代购平台是会员数据主数据源，服务平台是物流+WMS执行方，数据单向同步
2. **多租户方案：** 单表 + tenant_id隔离，不分表；所有查询必须带tenant_id
3. **双状态模型：** status（正常/禁用，人工控制）+ sync_status（未同步/已同步/同步中/同步失败，系统控制），职责分离不冗余
4. **邮箱必填：** 所有会员必须有邮箱，不允许null邮箱会员。第三方登录未返回邮箱时，强制用户手动输入邮箱并通过验证码验证归属权
5. **同步状态校验时机：** 登录时不校验sync_status，仅校验status。sync_status仅在业务节点（需要service_member_id的操作）检查并提示
6. **第三方登录：** 独立member_oauth_binding表，(provider, open_id)全局唯一。OAuth返回邮箱视为已验证归属权，未注册时直接创建会员+绑定+登录
7. **验证码去重：** 无邮箱路径下用户手动输入邮箱并验证通过后，绑定已有会员时不再重复发送验证码
8. **同provider拒绝换绑：** 同provider已绑定其他open_id的会员，拒绝验证码换绑，必须先登录原账号解绑
9. **注册即同步：** 注册时实时调用服务平台，非异步批量；自动重试3次（3秒/30秒/5分钟），超3次转人工
10. **运行时异常区别处理：** 注册同步失败自动重试；运行时服务平台异常不自动重试，标记失败引导联系客服
11. **不同步注销：** 代购平台注销会员不通知服务平台
12. **业务数据只读：** total_purchase_orders/total_package_orders/total_spend/balance/pending_packages等由订单/仓库/支付模块异步更新，会员模块不直接写入
13. **详情页结构：** 固定头部 → 基本信息区域（非Tab，始终展示） → 数据概览横幅（左右分栏） → 9个Tab（代购订单、提包单、余额明细、积分明细、优惠券明细、消费记录、售后记录、第三方授权、收货地址）
14. **列表页变更：** 删除"导出会员"和"新增会员"按钮；删除"注册渠道"筛选项和"手机号"列；新增集运会员ID、租户ID、注册端口、余额、累计提包单列
15. **新增数据表：** member_shipping_address（收货地址表），含实名认证字段is_verified和加密身份证号id_card_number
16. **member表新增字段：** default_warehouse（默认仓库）、default_currency（默认币种）
17. **实名认证：** 调用台湾易利委接口，用收货地址的身份证号+姓名验证，验证成功记录实名状态
18. **第三方授权支持6个平台：** Line、微信、Facebook、Google、抖音、TikTok，支持解绑操作
