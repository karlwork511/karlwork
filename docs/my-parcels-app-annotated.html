页面总说明
总览 ▶
功能说明
APP端用户查看和管理所有包裹的列表页，支持按状态筛选和关键词搜索
字段/展示规则
  • 顶部导航栏（标题「我的包裹」+ 返回按钮）
  • 搜索框（支持关键词搜索）
  • 横向状态标签栏（含数量角标）
  • 包裹卡片列表（按下单时间倒序）
交互规则
  • 搜索支持包裹单号 / 商品名称 / 国内快递单号
  • 状态标签切换实时筛选列表
  • 卡片整行可点击进入详情页

搜索区
交互 ▶
标注位置
搜索框区域 .search-section
功能说明
关键词搜索包裹
字段/展示规则
  • 搜索框占位文案：「搜索包裹单号 / 商品名称 / 国内快递单号」
  • 右侧搜索图标 🔍
交互规则
  • 输入后实时筛选列表
  • 清空搜索框恢复全部列表
  • 搜索无结果时显示空状态：「未找到相关包裹」 + 副标题「换个关键词试试」

状态标签筛选
交互 ▶
标注位置
状态标签栏 .status-tabs
功能说明
横向滑动标签栏，按包裹状态筛选
字段/展示规则
  • 标签列表：全部、待付款、待审核、处理中、待发货、已发货、已收货、已取消
  • 每个标签右侧显示数量角标（该状态下包裹数量），角标始终存在
  • 已收货不显示角标
交互规则
  • 点击标签切换列表，标签高亮
  • 某状态下无包裹时，列表区域显示：「暂无XX的包裹」（如"暂无已取消的包裹"）

包裹卡片结构
展示 ▶
标注位置
任意一个 package-card
功能说明
每个包裹以卡片形式展示核心信息
字段/展示规则
  • 卡片头：状态标签 + 包裹单号 + 下单时间
  • 商品信息：缩略图 + 商品名 + 规格 + 件数
  • 物流信息：线路名称 + 承运商 + 重量/体积
  • 费用信息：费用标签 + 金额
  • 操作按钮区：根据状态显示对应按钮
业务规则
  • 卡片按下单时间倒序排列
5
费用展示规则
展示 ▶
标注位置
package-fee 区域
功能说明
不同状态下费用展示逻辑不同
状态说明
  • 待付款 → 展示「需付款 ¥XX」
  • 已付款（待审核/处理中/待发货） → 展示「实付款 ¥XX」
  • 已发货/已收货 → 展示「实付款 ¥XX」
  • 已取消 → 展示「应付款 ¥XX」
补款提示
  • 存在补款时，在费用行下方增加补款提示条
  • 内容：「⚠️ 需补款 ¥XX」+ 「去补款」按钮
6
操作按钮规则
交互 ▶
标注位置
package-actions 区域
功能说明
根据包裹状态展示对应操作按钮
状态说明
  • 待付款 → 「取消包裹」「去支付」
  • 待审核 / 处理中 → 「取消包裹」
  • 待发货 → 无操作按钮（仅有补款提示条时显示「去补款」）
  • 已发货 → 「确认收货」（APP端没有"查看物流"按钮）
  • 已收货 / 已取消 → 无操作按钮
交互规则
  • 取消包裹 → 确认弹窗
  • 去支付 → 收银台
  • 去补款 → 补款确认弹窗 → 收银台
7

交互 ▶
标注位置
包裹卡片整体
功能说明
整行可点击跳转详情
交互规则
  • 点击卡片任意位置（操作按钮区域除外）→ 跳转包裹详情页
  • 操作按钮和补款提示条上的按钮阻止事件冒泡，不触发跳转
8
补款确认弹窗
交互 ▶
标注位置
补款确认弹窗本身
功能说明
用户点击「去补款」后弹出，确认补款信息后跳转支付
字段/展示规则
  • 标题：「补款确认」
  • 原包裹信息：包裹单号、下单时间
  • 补款原因 — 由后台发起补款时填写的备注信息决定，前端直接展示
  • 补款金额明细 — 展示附加费类型及对应金额（如"运费差额 ¥85.00"），多种附加费时逐行列出
  • 合计需补金额
  • 底部「取消」和「确认补款」按钮
交互规则
  • 确认补款 → 关闭弹窗 → 跳转收银台
  • 取消 / 点遮罩 → 关闭弹窗
9
空数据与搜索无结果状态
展示 ▶
标注位置
包裹列表区域的空状态示例
功能说明
列表为空或搜索无结果时的占位提示
字段/展示规则
  • 全局无包裹（所有标签下均无数据）：📦 +「还没有包裹」+「提交包裹后，这里会显示你的包裹信息」+「去提交包裹」按钮
  • 某状态标签下无包裹：📦 +「暂无XX的包裹」（如"暂无已发货的包裹"）
  • 搜索无结果：📦 +「未找到相关包裹」+「换个关键词试试」
交互规则
  • 全局无包裹时「去提交包裹」按钮可点击跳转
  • 其他空状态仅展示，无交互
