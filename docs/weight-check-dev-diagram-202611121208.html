核重补差（方案二：集运单支付控制）· 开发说明图

集运侧仅 1 个接口开发：②集运单支付（①④现有） 不补款地区数据库可配置（当前仅台湾、中国） 版本 v1.4 2026-11-12 依据：方案二 v1.0 ＋ 改造清单 v1.9 ＋ PRD v1.5

一句话本质：国际件集运单默认「未支付」，未支付不发货——这就是天然拦截。代购侧核重判定后，无需补款就直接支付集运单放行；需要补款就等用户补款到账后再支付放行。支付动作即放行关卡。

多退

无差额

直接调②支付集运单 → 发货④

少补

生成补款单，集运单保持未支付（拦截中）→ 通知用户补款 → 补款到账（现有闭环：关提示、待补款→已补款）→ 串联调②支付集运单（N5）→ 发货④

  • 续重判定：实际重量增量不足一个续重单位 → 不补款直接放行；≥1 个续重单位按超出档数 × 续重单价补款。
  • 补款无有效期，待补款提包单不自动取消（集运对超期未支付无自动处理规则，已确认）。
  • 二次核重：以最新一次回传为准，已退/已补差额按最新结果冲正。
  • 支付接口调用幂等（重复调用不重复支付）。
  • 地址无法识别国家/地区时，按「未命中配置」处理并记录告警日志。

地区列表落库，平台运营在后台自行新增 / 停用，判定实时读取最新配置——新增地区无需发版。

判定读取方式

  • 核重判定时以收货地址国家/地区匹配「启用状态」的地区条目
  • 命中 → 走放弃少补分支（少补不生成补款单，记录核实重量）
  • 未命中 → 走支付控制分支（少补卡「待发货 + 待补款」）

  • 配置地区少补的资金口径：用户不补、租户基准成本不重核，差额平台承担

5资金联动规则

铁律：用户侧与租户基准成本同方向、同差额，均生成流水并单向通知租户——唯一例外是命中配置地区少补：用户不补、租户基准成本不重核，差额由平台承担。平台↔集运为线下结算，与系统无关。

手动关闭预估运费全额退余额基准成本全额退回原集运单手动作废（集运现有流程）

6手动关闭（拒补换线兜底 · N7）

罕见场景，最简实现。入口在提包单详情页，动作不可逆，必须二次确认。

  1. 提包单状态 → 「已关闭」（新增状态，区别于已取消）
  2. 预估运费全额退余额
  3. 补款单作废
  4. 关联商品不释放，无法二次提包（规则固定，不做可选项）
  5. 操作留痕（操作人 / 时间 / 原因）
  • 与拒补换线天然吻合：集运重赋新单号＋无主件入库＋手动作废原集运单 → 代购手动建单关联 → 关闭原提包单 → 用户对新包裹重新提包，旧商品记录锁死即闭环。

二次确认弹窗（文案须明示三项后果）

确认关闭该提包单？

  • 关闭后提包单将关闭，不可恢复
  • 已支付运费将全额退款
  • 关联商品将无法二次提包
取消确认关闭
