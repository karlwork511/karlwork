需求概述

用户初次打开 APP / H5 / PC 端时，系统按「设备语言优先、归属地补充」自动判定最合适的界面语言与展示币种；判定结果持久化存储，之后按用户偏好展示，不再自动切换。界面语言与账号通知语言为两套独立数据。

核心规则

1. 两套数据分离

数据存储用途谁来改
界面展示语言（含展示币种）当前端本地记住当前端的界面展示初次自动判定；用户在端内手动切换
通知语言账号（用户表独立字段）系统发送邮件、短信、站内信、推送时的模板语种初始值取注册成功那一刻当前端生效语言（自动回填）；用户在个人信息中独立修改
币种偏好账号（用户表独立字段）记录用户注册时的展示币种（初始化记录，不驱动界面展示）初始值取注册成功那一刻当前端生效币种（自动回填）；之后用户在个人信息中修改

2. 初次自动判定链

设备语言精确匹配 → 主语言匹配（如 zh-HK → 繁体中文）→ IP 归属地目的国映射 → 全局默认。币种只看归属地，不看设备语言。判定只在端内无记忆时执行一次。

3. 两级兜底

国家级映射（目的国规则页逐国配置，正式推广的目的国必配）→ 全局默认（后台可配，推荐初值英语 + 美元）。任何情况下不允许出现无语言可展示的空态。

4. 注册时刻自动回填（v1.5 修订）

原「选择语言及币种」页确认不存在（PC 端亦无此设计）。注册成功那一刻，系统自动以当前端正在生效的语言/币种回填账号通知语言与币种偏好初始值；无确认页面、无额外交互；注册发生在哪一端就取哪一端当时的生效值。存量用户（功能上线前已注册）账号字段为空 → 通知按全局默认兜底，可在个人信息自行补录。

5. 单向同步边界

  • 个人信息修改语言/币种 → 账号字段更新，且当前端展示同步切换（写端内记忆，立即生效）
  • 端内切换语言/币种 → 只写端内记忆，不回写账号字段
  • 登录/登出 → 不触发任何切换，也不读写任何语言字段
  • 同步仅限当前端，不做跨端同步

6. 通知语言取值

  • 注册验证码 → 按当前操作界面的语言发送（账号尚未创建，无值可查）
  • 其余所有通知（登录/找回/换绑验证码、订单/物流/售后/营销等）→ 统一查账号通知语言
  • 账号通知语言为空 → 按全局默认语言发送，不允许因空值导致发送失败

功能清单

编号功能说明
FR-01用户端初次打开自动判定语种与币种判定链四种顺序全覆盖，判定一次后记住
FR-02用户端语言/币种切换立即生效并记住，不影响账号字段与其他端
FR-03个人信息-语言与币种管理单向同步：保存后账号更新 + 当前端同步切换
FR-04通知发送语言确定（系统行为）注册验证码用界面语言，其余查账号语言，空值用全局默认
FR-05管理后台-全局默认语种/币种配置后台可配，推荐初值英语 + 美元（配置落点待定）
FR-06目的国规则页迭代列表 + 弹窗新增默认语言/默认币种，必填，存量补录前按全局默认
FR-07注册时刻自动回填账号初始值（系统行为，无页面）注册成功那一刻以当前端生效值回填，之后不再回写
FR-08会员详情页迭代基础资料新增默认语言（只读，= 账号通知语言）

边界与不做

  • PRD 只约束业务要求，技术实现由开发自行设计
  • 多币种仅展示层按汇率换算，不做真实多币种结算
  • 不做初次打开提示条；不做跨端同步
